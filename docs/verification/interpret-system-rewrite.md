## 1. 为什么只改这一个常量

`src/index.js` 里混着两层东西：

| 层 | 内容 | 处置 |
|---|---|---|
| **部署级契约** | 三个工具的 `name`/`description`/`parameters`/`execute`、`/占` 斜杠命令、面板 HTTP 端点、`uiOnly` 行、`AGENT_SYSTEM`、`PLAN_SYSTEM` | **一律不动**（`test/host.mjs` 逐条断言，属冻结契约） |
| **方法论 / 提示词层** | `INTERPRET_SYSTEM` —— 规定模型如何解读合盘 | **本次重写**（原样是 v1 遗留，一条调研做法都没进去） |

重写只替换 `INTERPRET_SYSTEM` 的字面量（`grep INTERPRET_SYSTEM src/index.js` 仍恰好 2 处：定义 + `collectLlm` 调用处）。
两条被 `host.mjs` 依赖的字面量**原样保留**：

- `system.includes('综合判词')`（骨架标题，host 第 629 行）
- `system.includes('只能来自合盘')`（红线 1，host 第 630 行）

> 出处标注写在**代码注释与本文档**里，**不写进提示词**：提示词是发给模型的，塞仓库名只会诱使模型在判词里复述这些名字（反而污染输出）。

## 4. 字段可见性审计（硬约束 2）

骨架里出现的每个字段，都必须能在 `buildBoardBrief()`（`src/index.js` 第 384 行）或它输出的「断语」里找到：

| 骨架用到的量 | 简报里的可见形式 | 位置 |
|---|---|---|
| 综合判定/分门加权分/一致性/置信 | `综合：<verdict> <±score>　一致性 x　置信 y` | `buildBoardBrief` |
| 票型 | `票型：吉 a ｜ 平 b ｜ 凶 c` | 同上 |
| 五行旺缺 | `五行：…（X旺 Y缺）` | 同上 |
| 断语（含「体系分歧」「N法/M门」） | `断语：<advice>` | 同上；`advice` 由 `aggregate.js#buildAdvice` 生成，内含 `多法同现：key(N法/M门)` 与 `体系分歧：…相差 N 分` |
| 多法共识 | `多法共识：key×N法(±avg)` | 同上 |
| 应期 | `应期（最重要…）：text×N法` | 同上 |
| 分类加权 | `分类加权：<cat><±score>` | 同上 |
| 最大分歧 | `最大分歧：<cat> <高> ↔ <低>` | 同上 |
| 保真度 `⚠` / 未起 | 108 法明细行首的 `⚠`、判定列的 `未起` | 同上 |

**未引用**（因为没进简报，写了模型也看不到）：`divergence.familySkew`、`overall.rawScore`、`consensusKeys.fams`、`evidenceDigest`、`meta.agreement`。
（`familySkew` 的语义已由 `advice` 里的「体系分歧」承担 —— 条款 9 引用的正是后者。）

> 说明：任务书提到「`divergence.familySkew` 绝对值 ≥12 须显式说明某一法门在影响结论」。该字段**没有进简报**，且本次不得改简报生成器；故条款 9 改为引用**简报里真有的**两个可见量（断语内嵌的「体系分歧」与「分类加权」门间背离），语义等价且可执行。
