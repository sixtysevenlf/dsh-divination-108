## 1. 现象（修前）

```
问题「」/「   」/「。」/「嗯」→ #99 五格剖象 / #100 三才配置 / #101 生肖姓名学 未起（本法无解）
问题「这次合作能不能成」      → 三法正常起（因为问句里有汉字可"取象"）
```

即：**「没报姓名」被当成了「本法无解」**。这与契约 §2.2 的诚实降级原则不符 ——
没报的输入不许假装有，但也不该因此**不算**；正确做法是**降 `approx` 并明说取象替代了什么**，
与 `#92/#93`（未报所测之字·取象）、`#95/#96/#97`（未报外应·取象）保持同一风格。

## 2. 根因

`resolveName()`（`xiangxing.js`）在三条降级路径之后**最后一句 `return null`**：
- ① 问句有「问名意图」→ 正则提姓名（实名，正确路径，不动）；
- ② 有报数 → 借报数当笔画（已有，标 `approx`）；
- ③ 问句有可滤出的汉字 → 按所问文字取数（已有，标 `approx`）；
- ④ **连汉字都没有（空问句／纯标点／纯语气词）→ `return null`** ← 问题所在。

`wuGe` / `sanCai` / `shengXiaoName` 三个引擎都是 `const nm = resolveName(chart); if (!nm) return null`，
于是 ④ 直接变成 runner 的「本法无解」。

## 3. 修法（最小改动，只改 ④ 与三处输出标注）

### 3.1 ④ 改为「按盘上时间信息取象」

```js
// 连问句文字也没有（空问句／纯标点／纯语气词）→ **不可返回 null**
const dayGan  = String(chart?.dayGan  ?? '').slice(0, 1)   // 日干代姓
const hourZhi = String(chart?.hourZhi ?? '').slice(0, 1)   // 时支代名
const xi = [dayGan, hourZhi].filter(c => /[\u4e00-\u9fff]/.test(c))
return { chars: xi.length ? xi : ['甲','子'], source: 'text', approx: true, real: false, xiang: true, ... }
```

- 走 `source: 'text'` → 复用既有的 `resolveStrokes` 字码取数分支（`approx: true`），不新增笔画逻辑。
- `hourZhi` 由 `chart.hourZhi` 保证非空（历法层必产），故 `chars` 至少 1 字，不会退化成空数组。
- **绝不从问句取字**：该分支的输入本身就没有可滤汉字，故不会重演 v1「把『这次和』当姓名」的错。

### 3.2 三条路径统一加 `xiang` 标记 + 输出三处标注

| 位置 | 改动 |
|---|---|
| `resolveName` 的 ②③④ 三条降级路径 | 加 `xiang: true` 与 `xiangNote`（写明被什么替代） |
| `#99/#100/#101` 的 `essence` | 冠 `未报姓名·取象：` 前缀（与既有 `未报…·取象：` 同风格） |
| 三引擎 `detail` | 新增 `取象` 字段：有姓名时为 `null`，无姓名时写明替代物 |
| 三引擎 `fidelity` | 加入 `nm.approx` 条件 → 名义路径一律 `approx`（**原先 ② 路径的 `#99/#101` 仍报 `core`，与「降 approx」要求不符，已一并修正**） |
