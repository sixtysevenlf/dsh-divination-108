## 三、占星：算法与精度（可复现）

### 3.1 换了什么

| 项 | v1 | v2 |
|---|---|---|
| 日/月 | 平黄经＋中心差（太阳）／平黄经（月亮，误差可达数度） | astronomy-engine **地心视黄经**（ECT，含光行时/光行差） |
| 行星 | 水/金/火 平黄经直接当地心黄经 | 水/金/火/木/土 五颗**地心视黄经** |
| 恒星时 | 无（用「时角×15°」硬凑） | `SiderealTime`（IAU 1982 GMST）＋经度 → LST → RAMC |
| 上升 | `λ☉+90°+(时−12h)×15°`（正午近似，误差可达一个星座以上） | 标准上升式 `atan2(cos RAMC, −(sin RAMC·cos ε + tan φ·sin ε))`，**报了纬度才用真值**，未报退赤道面值并列 20/30/40/50°N 候选 |
| 中天 | 无 | `λ_MC = atan2(sin RAMC, cos RAMC·cos ε)`，**与纬度无关、精确** |
| 黄赤交角 | 无 | Meeus (22.2) 低精度式 |
| 入座时刻 | 平均运动折算天数 | `SearchSunLongitude` 精确求根 |

### 3.2 已核验的数字（同一出生资料 1990-05-12 09:30）

| 核对项 | 结果 |
|---|---|
| 恒星时**双通路**：astronomy-engine `SiderealTime` vs Meeus (12.4) 多项式 | **差 0.7 秒时**（每次求占都写进 `detail.evidence`） |
| 与历法层 `chart.birthChart.astro` 对拍（同一出生时刻） | λ☉ 差 **0.00000°**、λ☾ 差 **0.00000°**（逐位一致，evidence 里带数值） |
| 与契约 §6 oracle 表（1990-05-12 09:30 CST） | 太阳 **51.079°** vs 表载 51.08°；木星 **98.899°** vs 98.90°；土星 **295.298°** vs 295.30° —— 三项全中 |
| 上升公式恒等式 | φ=0 ⇒ λ_Asc ≡ RAMC+90（代码注释与 detail 均写明） |
| 出生时刻口径 | **与 `core/calendar.js` 的 `birthChart` 同口径**（宿主本地民用时），故可与历法层逐位对拍；出生地经度只用于 LST |

### 3.3 精度现状（诚实）

- **日月五星**：星历本身精度远优于本插件所需（视黄经优于角秒级），瓶颈在「出生钟表时→绝对时刻」的时区：插件无出生地时区输入，按宿主本地民用时解释（与历法层一致）。跨时区出生资料会有整小时级偏差（月亮约 0.5°/h、上升约 15°/h），**detail 里照实写明口径**。
- **中天 MC**：与纬度无关，仅受经度与恒星时影响 —— 本插件给的是精确值。
- **上升**：需要纬度。报了（问句含「北纬40」等）→ 精确且 `fidelity:'full'`；未报 → 赤道面值（取象，`fidelity:'core'`）并给出四个纬度候选。这是本模块**唯一**的主要近似来源，已写进 detail 与本节。
- **宫位**：等宫制（自上升起 30°），非 Placidus；宫名沿用 `tables.js ASTRO_HOUSES`。

## 七、遗留风险（诚实声明）

1. **签谱/辞书仍未内置**：#83–89 永远只有「签号＋签级＋卦象＋断语」，**没有签诗原文**。要出原文必须外部提供可靠签谱 JSON（当前实现已预留 `params.system` 选择签种）。这是本族保真度上不去的唯一原因，**不建议用生成的签诗冒充**。
2. **解梦/鸟占/眼跳/喷嚏为通书系统编辑取值**：本插件没有《玉匣记》等原书影印，表值是按通行版本编辑的；各地方版本互异，换师承需改 `./data/zhanbu.js` 的表（算法不用动）。
3. **笔画表缺失**：测字·笔画在「未报笔画且未报数」时用字码替代法 —— 结果确定、可复现，但**不是真笔画**；detail 每次都点名这一点。
4. **上升点依赖出生地纬度**：未报纬度时给赤道面值 + 四候选，属取象；这不是精度问题而是**输入缺失**，不应被读成「实测上升」。
5. **出生时区**：按宿主本地民用时解释（与历法层一致）。跨时区出生资料会产生整小时级偏差，detail 已写明口径；若日后加「出生地时区/经纬」输入，本模块的 `ctx` 已预留 `lonDeg`/`latDeg`，只需把时区一并传入即可升级。
6. **塔罗牌义倾向分、符文元素归属、容许度数值**均为本插件编辑取值（各处已标），不是传统数值；不要当作占星/塔罗的「标准答案」。

## 八、task-15 修复记录（verifier #2 FAIL 2/3 ＋ verifier #1 的 [高]）

### 8.1 `#95/#96/#97`：区分「完全未报」与「部分报」，并认用户的文述

**现象**：用户**报了**外应却仍标「未报外应」；`#97` 更严重——用户明说「三个喷嚏」，取象值却写「4 声」，**与用户输入矛盾**。

**修法（三法统一为分档口径）**：只有「本法兆象与附加信息**皆未报**」才用冻结前缀 `未报外应·取象：`（＋`approx`）；
报了兆象但缺附加信息时改用**如实措辞**，并一律降 `approx`（因为补的信息是取象）：

| 法 | 皆未报（smoke 冻结） | 部分报（新增分支） |
|---|---|---|
| #95 鸟占 | `未报外应·取象：` | `报鸟种未报方位·取象：` / `报方位未报鸟种·取象：` / 本表无其种时 `报鸟未报鸟种、方位·取象：` |
| #96 眼跳占 | `未报外应·取象：` | `报眼跳未报左右·取象：` / `报眼别未报眼跳·取象：` |
