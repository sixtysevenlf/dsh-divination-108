## 本轮对拍发现并处理的三个既有缺陷

### 1. 月柱换月口径（**已修**）

`vendor/lunar.cjs` 的 `getMonthInGanZhi()` 是在**节令当日 0 点**换月，不是节令**时刻**。
实例：`1900-07-07 08:42`（小暑未到）→ 旧口径给 `癸未`（未月），按时刻应为 `壬午`（午月）；
`1921-11-08 02:33`（立冬未到）→ 旧口径 `己亥`，应为 `戊戌`。每年 12 个节令，各约 0.5–1 天的错窗口。
v2 改用 `getMonthInGanZhiExact()`（按时刻换月），与"年柱按立春时刻换年"同一直径，且与 tyme4ts、与太阳视黄经分宫一致。
（契约 §6：改动须能被经典规则解释 —— 定气换月即经典规则，故成立。）

### 2. 晚子时日柱/时柱不同源（**发现，未擅改**）

`vendor/lunar.cjs` 在 23:00–24:00：

- `getDayInGanZhi()`（v1 日柱）→ **当日**干支（流派二）；
- `getTimeInGanZhi()`（v1 时柱）→ 用**次日日干**起子时（流派一口径）。

即 v1 盘在晚子时是"两派各取一半"，日建与（时柱隐含的）日干互相矛盾。
**v2 未改** `chart.ganzhi.day` / `chart.ganzhi.hour`（契约 §3.1 只许加不许改；改日柱会波及 108 法的日建/旬空/神煞），
改为把两派自洽解都放进 `chart.dayBoundary`：

```js
chart.dayBoundary = { lateZi, earlyZi, hourZhi, hour, convention,
  dayGZ, dayGZSchool1, dayGZSchool2, hourGZ,
  school1: { day, hour },   // 晚子时算次日（子平主流），日柱与时柱同源
  school2: { day, hour },   // 晚子时算当日，日柱与时柱同源
  selfConsistent,           // v1 的 (日柱,时柱) 是否同源；晚子时为 false
  note }
```

命理类要严格自洽，用 `school1`（或 `school2`）整组替换，不要只换一柱。
**这是留给 Lead 的决策项**：是否为全法统一切到 `school1`（会给 23:00–24:00 的日柱换日）。

### 3. 通书口径 vs 四柱口径（**已并列输出，不改 v1 字段**）

`vendor/lunar.cjs` 的 almanac 类字段走**通书口径**：交节日**当天**即换月建（日粒度）。
四柱月柱走**节令时刻口径**（定气）。二者在交节后约一天内不同，例如 `1900-07-07 08:42`（小暑未到）：

| 字段 | 通书口径（库/v1） | 四柱口径（v2 新增） |
|---|---|---|
| 月支 | `almanac.monthZhiTongshu` = 未 | `chart.monthZhi` = 午 |
| 建除 | `almanac.zhiXing` = 开 | `almanac.zhiXingExact` = 闭 |
| 黄黑道 | `almanac.tianShen` = 玉堂（黄道） | `almanac.tianShenExact` = 玄武（黑道） |

抽样中落在该窗口的样本 7/240 例（建除差 7、黄黑道差 7）。
**这不是谁错**：择日/黄历按通书（日粒度）看，八字/六爻/奇门按节令时刻看。v2 两套都留在盘上，
并给 `almanac.tongshuAgrees` 布尔位；`zhiXingExact` 已用 tyme4ts 独立验证到 240/240。
注意：`almanac.yi/ji/jiShen/xiongSha` 仍是通书口径（通书宜忌本就按日历日），未做双口径。

## 已知分歧与保留意见（诚实交代）

1. **二十八宿距星身份有异说**：本实现取维基/现代通说（心宿距星 = α Sco）。古星表另有以**心宿一（σ Sco）**为心宿距星者；改口径会使日躔入宿度整体移位。距星坐标源自 SIMBAD（ICRS J2000），逐条列于 `src/core/astro.js` 的 `SU28_STARS`。
2. **入宿度用赤道口径**：入宿度 = 目标赤经 − 距星赤经（传统"入宿度/去极度"体系）。同时输出黄经口径 `su28.ruDuByLon` 备参；二者在黄纬大的恒星（如尾宿距星 μ¹ Sco，黄纬约 −14°）附近可差十几度，**是口径差异不是 bug**。
3. **均时差与 v1 差可达 78 秒/年**：v1 用 NOAA 三项近似，v2 用 Meeus 精算（极值 2026：2/10 −14.15′、5/13 +3.70′、7/25 −6.55′、11/2 +16.46′，与天文年历吻合到秒级）。真太阳时落在时辰边界附近时可能与 v1 差一个时辰 —— 是修正而非回归。
4. **ΔT 在 1871–1902 为负**（1900 年约 −2.1 s），故"ΔT > 0"不是合法断言；实现用 astronomy-engine `DeltaT_EspenakMeeus`。
5. **神煞表为"通行口诀本"**：28 种神煞逐条带 cite，但**未与影印本逐字校勘**（`chart.meta.shenshaSource = verified:common-form`）。天乙贵人（庚作丑未/午寅）、羊刃（阴干取冠带/临官）、血刃等条有异本，已在各条 `note` 标注；据此下重断时方法层应自行降 `fidelity`。
6. **`chart.astro` 的时刻基准是 `when`**（求占绝对时刻），不是真太阳时 `solarDate` —— 真太阳时"改钟不改天"。
7. **tyme4ts 与 lunar.cjs 同作者**：B 通路一致不证明"更准"，只证明"不同实现同结论"；真正独立的证据是 C 通路。
8. **契约 §6 的 oracle 数值以 UTC+8 固定偏移为前提**（verifier #2 独立复现、此处存档）：§6 所载 1990-05-12 09:30 CST 的「太阳 51.08°、木星 98.90°、土星 295.30°」，是在**出生民用时刻按 UTC+8 解释**下成立；若在 `TZ=UTC`／`America/New_York` 的机器上把同一串数字当"宿主本地时间"解释，会得到 51.40°／51.56° —— 那不是实现错，是输入的时区语义变了。v2 已把出生时刻固定为 +8 偏移（**不查时区库**，免历史 DST 干扰），故本报告数值在任何机器上可复现。
9. **出生时刻口径（task-14 已修）**：原实现用 `new Date(y,m-1,d,h,mi)` 按宿主时区解释 `birth`，同一份出生资料跨机器得到不同黄经（极端例：名义同为 +8 的 `Asia/Shanghai` 与 `Etc/GMT-8`，因中国 1990 年夏令时差 1 小时）。现改为 `Date.UTC(...) − 8h` 固定偏移；`renyuan` 的"自节令起日数"改用两端同口径的民用时刻差（原本地 Date 相减会被 DST 抖 ±1h）。口径落点：`calendar.js` 文件头「时间口径」表、`birthChart.tz`、`meta.timeConvention`。
