### V2-04 · 出生时刻按**宿主本地时区**解释 → 跨机不可复现，且契约 §6 oracle 未标时区前提

| 项 | 内容 |
|---|---|
| 严重度 | **中–高**（跨机不一致 + 文档化 golden 值在别的机器上失败） |
| 责任方 | `src/core/calendar.js`（kernel-astro）＋ `docs/V2-CONTRACT.md §6` 的 oracle 表述 |
| 现象 | 同一份出生资料 `1990-05-12 09:30`，在四种宿主时区下得到**四个不同的 UTC 瞬时与太阳黄经**： |

| 宿主 TZ | 解释出的 UTC 瞬时 | 太阳黄经 | 木星 | 土星 |
|---|---|---|---|---|
| `Etc/GMT-8`（本机默认） | 1990-05-12T01:30Z | **51.07922** | 139.460 | 11.633 |
| `Asia/Shanghai` | 1990-05-12T00:30Z | 51.03899 | 139.460 | 11.633 |
| `UTC` | 1990-05-12T09:30Z | 51.40103 | 139.520 | 11.607 |
| `America/New_York` | 1990-05-12T13:30Z | 51.56192 | 139.550 | 11.594 |

- **根因**：`calendar.js` L748 `const birthDate = new Date(b.y, b.m - 1, b.d, b.h ?? 12, b.mi ?? 0, 0)` —— 用 `new Date(y,m,d,...)` 即**宿主本地时区**解释，再交给 astronomy-engine 当瞬时用。
  `Asia/Shanghai` 与 `Etc/GMT-8` 同为 UTC+8 却相差 1 小时，是因为**中国 1990-04-15～1990-09-15 实行夏令时**（历史 DST 规则参与解释）——这条尤其隐蔽。
- **契约 §6 的 oracle（太阳 51.08°、木星 98.90°、土星 295.30°）只在本机 `TZ=Etc/GMT-8`（固定 UTC+8、无 DST）下成立**；换机即不成立，但 §6 未标注时区前提。
- **影响面**：#105–#108 西方族、以及一切读 `chart.birthChart.astro` 的法门（命理族诸法亦然）。
- **注**：`Angular` 一致性仍在——同机同参两次求占结果完全一致（本文件 §1/§5 与 smoke 均验证）；问题在**跨机**。
- **建议**：(a) 出生时刻按**显式声明的参考时区**解释（中式术数惯用 UTC+8 的固定偏移，**不用**历史 DST 规则）；或 (b) `chart` 新增 `birthTz`/`utcOffset` 字段并在 `divine` 工具描述里暴露；并 (c) 在契约 §6 的 oracle 表头注明「下列值在 TZ=UTC+8 固定偏移下成立」。
- **复现**（进程内切换 TZ 即可，无需多机）：
  ```powershell
  node -e "const C=require('./src/core/calendar.js');" # ESM 见下
  node --input-type=module -e "import('./src/core/calendar.js').then(C=>{for(const tz of ['Etc/GMT-8','Asia/Shanghai','UTC','America/New_York']){process.env.TZ=tz;const c=C.buildChart({question:'x',when:new Date(2026,8,30,14,30),longitude:116.4,birth:{y:1990,m:5,d:12,h:9,mi:30}});console.log(tz,new Date(1990,4,12,9,30).toISOString(),c.birthChart.astro.sunLon)}})"
  ```
