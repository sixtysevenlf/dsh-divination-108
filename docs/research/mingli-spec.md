### A.1 真太阳时修正

**⚠ 重大发现：所有被调研的仓库都没有实现「均时差」修正。** 全库检索 `equation of time` / `均时差` **零命中**（对 `D:\DSH\.research-tmp\*` 全目录 grep 结果为空）。已实现的只有「经度差 × 4 分钟/度」：

- `ai-freer/fortune-skill:scripts/time-normalize.mjs:148-161`（**唯一真正实现真太阳时的仓库**）：
  ```
  const diff = longitude - stdLon;        // 正 = 偏东，负 = 偏西
  const correctionMinutes = diff * 4;     // 每度 4 分钟
  ```
  即 `校正分钟 = (当地经度 − 时区标准经度) × 4`；返回 `correctionMinutes` 与 `standardLongitude`。
  调用顺序（同文件 `:200-234`）：① 先减去 DST 偏移 → ② 再加真太阳时校正 → ③ 再算时辰。
  城市不在内置表时：警告"跳过真太阳时校正"，不报错（`:267-272`）。
  **未实现均时差（EoT）** → 全年最大 ±16 分钟的系统误差未处理。
- `jinchenma94/bazi-skill:scripts/pai_pan.py:51-52` 明确**不做**真太阳时：
  > 「真太阳时：默认钟表时间。若给了 `--place` 且时刻距时辰整点边界 ≤15 分钟，只加警告『校正后可能跨时辰』，不查经度、不做完整真太阳时。」
- `yanouyuan-bit/bazi-roundtable:scripts/paipan.py:20`：「真太阳时校正不在本脚本范围内：如需校正，请用户先按出生地经度换算后再输入」。
- `ml8s/liki` 只有 `docs/BAZI_MODEL.md:168` 提到「真太阳时或既定时辰距时辰交界 ≤30 分钟时返回 `calibration_hint`」，**是提示不是校正**；且明说「换日口径不在本层表达」（`:170`）。

**→ 重写建议**：`divine` 增加 `longitude` 参数时，必须**同时**做经度差与均时差（EoT ≈ ±16 min），否则边界时辰会系统性判错。

**EoT 的可行来源（本次调研已核实其存在性，但未逐行核实公式**）：

→ **不要**引用本次调研的任何源来实现 EoT（它们全都没做）。

### A.2 节气精确换月点（按太阳黄经 15° 整数倍）

`jinchenma94/bazi-skill:scripts/pai_pan.py` 是**唯一零依赖自行实现天文历算**的源，且质量最高：

- 十二节定义（`pai_pan.py:76-89`），`(黄经, 名称, 月支下标)`，寅=2 … 丑=1：
  ```
  (315,立春,2) (345,惊蛰,3) (15,清明,4) (45,立夏,5) (75,芒种,6) (105,小暑,7)
  (135,立秋,8) (165,白露,9) (195,寒露,10) (225,立冬,11) (255,大雪,0) (285,小寒,1)
  ```
  中气黄经：`ZHONGQI_LONGS = (0,30,60,90,120,150,180,210,240,270,300,330)`（`:91`）。
- 太阳视黄经（`:476-489`，Meeus AA 第 25 章简式，1900–2100 约 0.01° / 十余分钟）：
  ```
  T = (jd_tt - 2451545.0) / 36525.0
  L0 = 280.46646 + 36000.76983*T + 0.0003032*T²
  M  = 357.52911 + 35999.05029*T - 0.0001537*T²
  C  = (1.914602 - 0.004817*T - 0.000014*T²)*sin M
     + (0.019993 - 0.000101*T)*sin 2M + 0.000289*sin 3M
  Ω  = 125.04 - 1934.136*T
  λ  = L0 + C - 0.00569 - 0.00478*sin Ω   (再 % 360)
  ```
- 定气求解（`:498-515`）：以 `delta_lon = (target - 280.46646) % 360` 估初值
  `jd0 = 2451545.0 + (year-2000)*365.242189 + delta_lon/0.98564736`，
  在 `[jd0-8, jd0+8]` 内**二分 52 次**，判据 `_lon_delta(sun_apparent_longitude(mid), target) < 0`。
  注释明写：「立春 = 315°。禁止用『大约 2 月 3–5 日』这种写死日期」（`:502`）。
- ΔT（TT−UTC）分段多项式（`:410-438`，Espenak/Meeus，1900–2100 到分钟级），覆盖 1920/1941/1961/1986/2005/2050 六个分段。
- 力学时 → 北京时间（`:453-457`）：`utc_jd = jd_tt - delta_t_seconds(year)/86400`，再转 UTC+8。

**对照源**：`yanouyuan-bit/bazi-roundtable:scripts/paipan.py:19` 只说「年柱、月柱以立春/节（非中气）交接的**精确时刻**为界」，具体交给 `lunar-python`；并设「临近换节 ±12 小时」告警（`:108`）。
`6tail/lunar-javascript:lunar.js` 内含 VSOP 级级数（`:3069,3158,3171,3279,3291` 等大量天文系数表）与 `qiHigh/qiLow` 定气函数（`:3548,3562`），**未逐行核实**其完整实现。

### A.8 起运与大运（三天折一年，含按分钟折算）

**顺逆规则**（三源一致）：

- `jinchenma94/bazi-skill:pai_pan.py:1116-1121`：
  ```
  yang_year = (year_gan_i % 2 == 0)          # 甲丙戊庚壬为阳年

  ```
  口诀与表格见 `references/dayun-rules.md:9-18`（阳男阴女顺排，阴男阳女逆排）。
- 起运取「节」：`forward` 时用**下一个节**，否则用**上一个节**（`pai_pan.py:1124-1129`）。
- **大运从月柱的下一柱（顺）/上一柱（逆）起排，月柱本身是起运前小运**（`:36`、`:1029-1048`）。`build_dayun` 中 `delta = +1/-1`，首次循环即先移位。

**起运换算（粗粒度）** — `jinchenma94/bazi-skill:pai_pan.py:1016-1026`：
```python
whole = int(days); frac = days - whole
years, rem = divmod(whole, 3)
months = rem * 4 + int(round(frac * 4))     # 余 1 天 ≈ 4 个月，余 2 天 ≈ 8 个月
if months >= 12: years += months//12; months %= 12
```
文末规则（`references/dayun-rules.md:57-62`）：余 1 天≈4 个月、余 2 天≈8 个月、余 0 天整岁，并「四舍五入到最接近的整数岁数」。

**起运换算（精确到分钟，推荐）** — `6tail/lunar-javascript:lunar.js:5787-5832`，`getYun(gender, sect)`：
```
forward = (阳年 && 男) || (!阳年 && !男)                  # :5784-5786
start = forward ? birth_solar : prev_jie_solar
end   = forward ? next_jie_solar : birth_solar
# sect == 2（按分钟精确）：
minutes = end.subtractMinute(start)
year  = floor(minutes / 4320); minutes -= year*4320        # 4320 min = 3 天 → 1 年
month = floor(minutes / 360);  minutes -= month*360        #  360 min = 6 小时 → 1 月
day   = floor(minutes / 12);   minutes -= day*12           #   12 min = 12 分 → 1 日
hour  = minutes * 2                                        #    1 min → 2 小时(时辰刻度)
# sect == 1（按时辰粗算）：
hourDiff = 时辰差(end) - 时辰差(start); dayDiff = end.subtract(start)
if hourDiff < 0: hourDiff += 12; dayDiff -= 1
monthDiff = floor(hourDiff*10/30); month = dayDiff*4 + monthDiff; day = hourDiff*10 - monthDiff*30
year = floor(month/12); month -= year*12
```
→ 换算链：**3 天 = 1 年；1 天 = 4 个月；2 小时 = 10 天；1 时辰(2h) = 10 天**。
`sect` 归一（`:5782`）：`sect = (2 === sect) ? 2 : 1`（默认 1，传 2 才用分钟精算）。
`23:00` 特判为时支索引 11（`:5809-5810`）。

**交运时刻**：`jinchenma94/bazi-skill` 只输出「起运年龄（岁+月）」，**不输出交运日期**（未核实有交运时刻实现）。`lunar-javascript` 给出 `yun.getStartSolar()`（起运公历日期，`lunar.js:5917`；fortune-skill 调用见 `scripts/bazi-chart.mjs:777`），并据此推大运起始年：`startYear = startSolar.getYear() + (index-1)*10`（`lunar.js:5915-5932`）。
`roundtable:scripts/paipan.py:119-127` 打印 `yun.getStartYear()/getStartMonth()/getStartDay()` + `isForward()`。

**大运周期**：每步 10 年（`jinchenma94:references/dayun-rules.md:64-78`）；起运前用月柱作小运（`:80-84`）；「大运天干管前五年、地支管后五年」被明确标注为**一家之言**（`:98`）。

### G.3 紫微星定位（局数 × 农历日数）

### H.1 为什么做多学派（设计动机）

`yanouyuan-bit/bazi-roundtable:bazi-roundtable/SKILL.md:10`：

### H.2 流程：先立事实层，再分学派推演

**① 盘面事实层（准确性地基）** —— `SKILL.md:29-35`，三条硬规则：
1. **禁止徒手排盘**：用户只给出生时间时，必须运行 `scripts/paipan.py`（依赖 `lunar-python`）；「节气交接时刻、日柱、大运起排都不允许模型心算」。无法运行脚本的环境要求用户提供可信排盘结果并声明「本场以你提供的排盘为准」。
2. **流年干支必须查表**（`references/ganzhi-years.md`，1940–2060），禁止心算。
3. **开场先立事实层**：主持人先摆出「**盘面事实表**」：四柱、藏干、天干十神、旬空、大运表，以及脚本给出的**换节临近警告**。
   > 「这张表是四家共享的**客观层**——此后任何角色引用的合冲刑穿关系若与事实表冲突，**主持人当场纠正；分歧只允许发生在方法论层，不允许发生在『这两个字有没有相合』这种事实层**」（`:35`）
   → **这是整套设计的核心机制：事实层不可争，方法论层必须争。**

**② 角色阵容**（`SKILL.md:41-47`，四派 + 主持人 + 可选观众）：

| 角色 | 流派 | 方法论要点 | 已知偏差（被主持人盯） |
|---|---|---|---|
| 盲派 | 盲派（做功/宾主） | **作用关系 > 旺衰；贴近 > 遥隔；引动 > 静态** | 敢下凶断 |
| 格局派 | 子平格局法 | 月令为纲、格局成败、用神清浊 | **层次判断偏高**；细节类标注低置信或拒答 |
| 调候派 | 《穷通宝鉴》一系 | 寒暖燥湿、调候三字尺 | 自我定位「可证伪的假说集」 |
| 民国派 | 韦千里一系新派 | 白话直断、以验证为归；**每报一个数必须注明盘面出处** | 敢报具体数字 |

**③ 分歧是资产**（`SKILL.md:48`）：
> 「各流派**必须保持方法论上的真实分歧**，同一盘面允许得出相反结论……如果发现四家结论趋同，**主持人有义务追问『是各自推出来的，还是抄了同一个社会先验？』**」

**④ 交叉 review（冲突如何被制造）**（`SKILL.md:90`）：
> 「后发言的流派对先发言者提出**方法论异议（至少一条实质分歧，取材于争议矩阵 `disputes.md`）**」

**⑤ 八个环节**（`SKILL.md:89-96`）：
```
1 起盘总评（各流派轮流：格局、层次区间、喜忌到字、大运走势）
2 交叉 review（方法论异议，取材争议矩阵）
3 圆桌问答（主持人逐问，各家下断语，禁止含糊）
4 可证伪硬断轮（形貌/感情史/学历/行业等可验证项）
5 结账复盘（命主报实况 → 逐家对账 → 更新积分表；严禁倒推；写回档案）
6 前瞻预判（带概率、应期、事件类型的「风险清单」）
7 观众点评（元批评）
8 第二次批命（带实况重批：各家必须先写取舍规则、再写结论）
```
**互动式推进硬规则**（`SKILL.md:82-87`）：「**一次回复只走一个环节，绝不连播**」——理由是「结账复盘的价值取决于用户在硬断轮之前没有透露实况，一口气播完全部环节等于让各家在『已知答案』的污染下下注」。

### H.3 冲突如何裁决（**关键机制**）

**a) 争议矩阵 = 冲突燃料库**（`references/disputes.md:1-10`）：
> 「本文件是四派方法论分歧的**唯一权威来源**……每个争议**至少有两派互斥立场**；立场是**方法论承诺，不是辩论姿态**——角色被追问时必须能用本派框架自洽地守住（守不住就按认错规则处理）。同一争议被实况裁决后，**主持人在会议纪要『方法论看点』中记录裁决偏向哪派**。某派标注『无立场』时必须给出理由，且不得在场上临时编造立场混分。」

**九大争议**（`disputes.md`，每条都是 4 派立场并列）：
1. **辰土算不算木之根**（`:11-18`）：盲派「不算根，辰是水库湿土，乙木只算余气微根」/ 格局派「按司令与会合论，辰中乙木为余气有微根」/ 调候派「不谈算不算根，谈辰能养木」/ 民国派「**按余气计三分力，不搞有无之争**」
2. **合绊损耗几成**（`:20-27`）：盲派「功能冻结七八成以上」/ 格局派「合而不化减力约半」/ 调候派「减力三四成，但**寒暖之性不灭**（丙被辛合仍有暖意）」/ 民国派「**无统一折扣（声明无立场）**，逐盘验，拒绝先验定数」
3. **虚透之火如何断**（`:29-36`）：盲派「以象论不以力论」/ 格局派「虚透之神可为格所用，唯层次降等」/ 调候派「气候要的是温度不是力量」/ 民国派「**打七折计力，不归零**」
4. **旺衰要不要先定**（`:38-45`）
5. **空亡等神煞用不用**（`:47-54`）：盲派重空亡 / 格局派「神煞不入成败判断」/ 调候派「不用」/ 民国派「冗余，弃用」
6. **调候优先还是格局优先**（`:56-63`）：调候派「**失度严重时调候第一**；失度不严重时自认辅助」/ 格局派「格局为体、调候为辅」
7. **层次判断怎么锚定**（`:65-72`）：格局派四阶给区间 / 民国派要求用**可验证代理指标**（学历段、行业收入带、职级）
8. **细节题该不该答**（`:74-81`）
9. **燥湿是否独立于寒暖**（`:83-89`）：调候派「独立两轴，癸与壬的取舍由此分」/ 民国派「可并轴简化」

**b) 记分制与反倒推纪律**（`SKILL.md:65-74`，`references/discipline.md`）：
```
1 AI 普遍高估命主层次 → 层次判断给区间不给单点；全体偏乐观时主持人主动质疑共识
2 原局作用优先级把握不稳 → 流派间强制 counter-review；作用取舍必须写明优先级理由
3 大运流年结合原局不准 → 流年断语必须落到可验证的年份 + 事件类型
4 喜忌无法准确到字 → 禁止"喜金水"式表述；喜忌必须到字并附条件
5 顺着用户说 → 用户透露实况后，严禁事后倒推；认错必须干脆
6 从结果倒推理论 → 主持人在复盘中点名任何倒推行为；重批环节先写取舍规则、再写结论
```
记分从严（`SKILL.md:52`）：「**宽泛命中不邀功、边缘命中减分、『怎么都对』的话不入表**」。

**c) 输出格式规范（可证伪性的落地）**（`SKILL.md:102-110`）：
> **断语格式**：结论 + 概率/置信度（民国派必须、其他鼓励）+ 应期年份 + **可证伪条件**（「若……则记我错」）
> **悬案清单**跨轮滚动维护：未验证的赌注逐轮顺延
> **篇幅纪律**（软上限）：起盘总评每家 ≤250 字；交叉 review 每条异议 ≤150 字；问答/硬断轮每题 ≤120 字；主持人开收场各 ≤80 字

**d) 对「ai 含糊」的两个正面约束**（`SKILL.md:72`；`references/tiaohou.md:32-34`）：
- 「禁止『喜金水』式表述；喜忌**必须到字**并附条件（如『丙丁须坐巳午强根才起作用』）」
- 调候派专属纪律：「报调候字时必须**同时报该字在原局的状态**：透干与否、坐支何处、有无强根。『喜丙』是半吊子，『丙透坐寅长生、不受壬克，调候真得』才完整」；「表中之字虚透无根时，只能算『得半字』，断语置信度同步下调」

**e) 对 DSH 的直接启发（我的判断，非源文件原文）**：
`bazi-roundtable` 的机制可以**原样搬到 108 法合盘**：因为 `divine` 现在已有「票型 / 多法共识 / 分歧项」，但缺少 ①**事实层不可争的显式输出**（对照：bazi-roundtable 的盘面事实表）②**分歧项的派别归因**（哪两派在争、争的是事实层还是方法层）③**可证伪条件字段**。建议在合盘输出中为每个分歧项补 `layer: 事实层|方法层` 与 `falsifier` 两个字段。
