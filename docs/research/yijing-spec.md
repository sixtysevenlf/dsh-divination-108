### E2 R9 的时间卦公式原文【C·单源，且有偏差】

来源：R9 `meihua-prashna/scripts/build_prashna_data.py` L54-129。

```python

upper       = remainder(total_date, 8, 8)                      # 余 0 取 8
```

其中 `branch_number`：子时 = 1、丑 = 2 …… 亥 = 12（L59-64，23 点后与 0 点归子时）。

**⚠️ 偏差 1：用公历年份与公历月日，而非「年支序数 + 农历月 + 农历日」。**
传统时间卦为：上卦 = (年支数 + 农历月数 + 农历日数) ÷ 8 取余。R9 用 `dt.year`（如 2025）与公历 `dt.month`/`dt.day`。以 2025 年为例：`2025 mod 8 = 1` → 上卦取乾；而按年支，2025 为乙巳年、巳=6，结果不同。R9 自身在输出中如实写明「上卦: (2025 + 月 + 日) ÷ 8 余 N」（L149-151），所以这是**有意简化**而非隐藏 bug，但**不等于传统梅花**。

**⚠️ 偏差 2（真 bug）：变卦翻爻方向反了。**
`TRIGRAM_BITS`（L47-50）是**自上而下**编码（1→[1,1,1] 乾、2→[0,1,1] 兑、4→[0,0,1] 震 …，经验证恰为标准三爻的**逆序**）；而 `flip_trigram(number, position)`（L67-70）用 `bits[position-1]` 取位，`position` 又是**自下而上**的爻位（1 = 初爻）。两者方向冲突。

| 用生体 | 用方力量/行为/外部条件流向体方，可体现支持、靠近、供给、帮助；是扶助还是过度输入，要看卦意与旺衰 |
| 体生用 | 体方力量/情绪/资源流向用方，可体现影响、投入、供给、消耗；**不等于体方一定更主动** |
| 用克体 | 用方/外部条件对体方形成限制、压力、冲击、竞争；**不自动等于失败或恶意** |
| 体克用 | 体方对用方形成推动、约束、控制、施压；**不自动等于能掌控或一定成功** |
| 比和 | 体用处于相近或共振状态；可能协调，也可能同类相争，须结合本卦、动变、旺衰 |

**旺衰：月令 + 卦气**（L145-171）：
- 旺衰**不能只看月令**，要同时看 `月令`（外部时令、大环境）与 `卦气`（卦本身的内在气势与能量周期）。
- `日辰` 只是**补充项**，不是第一判断层。
- 典型修正：体旺用弱 → 即使用克体也可能克不动；体弱用旺 → 即使用生体也可能变成接不住的虚扶。
- 月令与卦气不一致时，**不要机械二选一**，分述各自把哪边往上托/往下压，最后只落一个实战问题：**体比用更强，还是用比体更强**。

**动爻位职责**（L177-183）：初=开端/起手；二=内部条件/配合；三=转折/卡点；四=外部关系层；五=核心结果/拍板层；上=收尾/过头/极端。动在下卦多从执行层开始变，动在上卦多往关系层/结果层走。

**互卦**（L208-218）：**不是终局，而是「事情内部正在怎样运作」**，用于补中段过程。表面顺而互卦阻 = 外顺内卡；表面阻而互卦顺 = 暗中有解；互卦生体 = 中途能借力；互卦克体 = 中途消耗大。
> ⚠️ R7 **未给出互卦的取法公式**（即取二三四爻为下卦、三四五爻为上卦），也未给错卦/综卦的定义式，只给了用法。

**错综**（L248-258）：只在经卦、变卦都难拉开倾向时才用。**错卦看反面风险；综卦看换位视角**。输出口径：同向支持 / 同向否定 / 方向分裂。
> 【B·多源一致】错卦 = 六爻阴阳全变（旁通）；综卦 = 全卦上下颠倒（反卦）。定义与 R7 表述一致，但**两个仓库都没有写出可执行的取法**，需自行实现。

**外应三级**（L220-246）：
| 级别 | 内容 | 权重 |
|---|---|---|

## 附：给重写者的三条架构建议（源自 R1/R3 的工程实践）

1. **确定性事实 vs 模型可调引导，必须分层**（R1 `build_model_packet.py` L119-135）：
   `chart` + `deterministicRuleFacts` 是**不可改写的确定性事实**；`routingGuidance`（用神候选、应期候选）标注 `authority: "advisory"`，模型可依原问题说明理由后调整，但**不得改写 chart**。R1 的 pipeline 显式列出五段：`deterministic_chart → deterministic_rule_facts → domain_method_guidance → free_model_interpretation → fact_consistency_review`。

2. **格局检测单一权威**（R3 SKILL.md 铁律 13）：特殊格局由脚本 `detect_patterns()` 检测并写入 JSON，**解读层直接读字段、禁止手动重新识别**（「两套逻辑会打架」）。R3 甚至为此设了自检：若 JSON `ben_liuchong_gua=false` 而报告写「本卦为六冲卦」→ 判矛盾。

3. **区分「结构候选」与「结论」**（R1 的 `conclusionScope` 标注）：如三合局输出 `conclusionScope: "structure_candidate_only"`、应期输出 `"conditional_timing_candidates_not_guaranteed_dates"`、候选比较输出 `"candidate_comparison_only_not_outcome"`。**把「算出的事实」与「据此下的判断」在数据层显式分离**，可避免 108 法合盘时把候选当成断语。
