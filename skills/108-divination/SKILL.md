# 108 术数合盘 · 操作手册

## 一、核心事实（先记住这三条）

1. **推演在插件里，不在你这里。** `divine` 一次调用会在本地算完 108 法，
   你拿到的是**算完的合盘**。你不需要、也不应该自己装卦、起局、发三传、排八字。
2. **结果是确定性的。** 同一个「问题 + 时刻 + 法号」必得同一结果。同问同刻再算
   一定一样；想换一卦就换措辞或换 `when`；想复核就把 `seed` 传回去。
3. **合盘是压缩过的。** 默认输出含 **108 行**紧凑明细（每行约 10-16 token）。
   **默认必须把这 108 行原样转述给用户**（用户要求「应多尽多」）；要某一法的完整盘用
   `divine_detail`。只有用户主动说"别啰嗦/只要结论"时才改用 `format="brief"`。

## 二、三个工具

### `divine` —— 求占主入口

| 参数 | 必填 | 说明 |
|---|---|---|
| `question` | ✅ | 所问之事。**写得具体**：它会用于术法加权与取用神。 |
| `when` | | 求占时刻 `YYYY-MM-DD HH:mm`（本地时间）。**缺省 = 这台机器的当前时间**，插件自己取；**不要为此问用户**。只有用户主动给了别的时刻才传。 |
| `longitude` | | 经度（东经正，如北京 116.4）。给了才做真太阳时校正。 |
| `birth` | | 出生资料 `YYYY-MM-DD HH:mm`。命理类需要。 |
| `gender` | | `男` / `女`。命理类用。 |
| `numbers` | | 报数（梅花报数卦、测字笔画）。 |
| `coins` | | 六爻钱面回放：六个 `6/7/8/9`。 |
| `scope` | | `all`（默认 108 法）/ `category:命理` / `module:yijing` / `ids:daliuren,qimen-shi` / `no:1,2,3` |
| `format` | | `brief` 只看断语 / `normal` 默认 / `full` 展开全部盘 / `table` 只要明细表 |
| `detail` | | 要一并展开完整盘的法，如 `奇门遁甲,31` |
| `seed` | | 复现种子。传上次返回的 `seed` 得完全相同结果。 |

返回：合盘文本 + `id`（记录编号）+ `verdict` + `score`。

### `divine_detail` —— 下钻

| 参数 | 说明 |
|---|---|
| `method` | 中文名（可模糊）、英文 id 或编号，逗号分隔多选，如 `奇门遁甲·时家,31`。 |
| `id` | 回看历史某次（`divine` 返回的 id）。缺省最近一次。 |
| `sort` | 不传 `method` 时的排序：`no` / `score`。 |

### `divine_list` —— 目录

参数：`category`（11 类之一）、`fidelity`（`full`/`core`/`approx`）。
用于确认某法是否支持、或向用户说明能算什么。

## 四、问法 → 参数映射

**默认一律 `format="normal"`（含 108 行明细）并把明细原样转述**；不要自己降档。

| 用户这样说 | 你这样调 |
|---|---|
| 「帮我算算这次合作能不能成」 | `divine(question="这次和张三的合作能不能成")` —— **不传 `when`**，用机器当前时间 |
| 「看看我的八字」 | `divine(question="看八字", birth="1990-05-12 09:30", gender="男")` |
| 「下周签约好不好」 | `divine(question="下周签约好不好", when="2026-10-06 10:00")` —— 用户给了具体日期才传 `when` |
| 「家里坐北朝南的风水」 | `divine(question="坐北朝南的房子风水如何")` —— **坐向写进 question** |
| 「抽个签」 | `divine(question="抽签问姻缘")`（7 个签种会各出一签） |
| 「我梦见蛇和洪水」 | `divine(question="梦见蛇和洪水，问吉凶")` |
| 「测个字，『明』」 | `divine(question="测字：明，问前程")` |
| 「我和他合不合」 | `divine(question="我和1992年3月15日生的人合不合", birth="...")` |
| 「帮我算一下，别啰嗦」 | `divine(..., format="brief")` |
| 「奇门盘给我看看」 | `divine(...)` 后 `divine_detail(method="奇门遁甲")` |

**注意**：
- 坐向、姓名、梦象、所测之字这些**没有独立参数**，一律写进 `question`，
  各法模块会从里面提取。
- 命理类缺 `birth` 会被记为「未起」（不占权重、不计票），不是报错。缺了就问用户。

## 五、合盘怎么读

```
◆ 综合：小吉 +18.4 ｜ 一致性 0.42 ｜ 置信 0.35 ｜ 覆盖 1
◆ 票型：吉 31 ｜ 平 46 ｜ 凶 31
◆ 五行：木12.3% 火18.1% ... → 金旺 木缺
◆ 断语：合盘总断【小吉】…；诸法分歧明显…；…
◆ 共识：官鬼动×9法(+21)、体克用×5法(+15) …
◆ 应期：7日内×12法、酉日×8法 …
◆ 分类：易卦+12 三式-5 命理+30 …
◆ 分歧：三式：奇门遁甲·时家+72 ↔ 太乙神数·九宫-68（差 140）
◆ 保真：全算法 36 ｜ 核心算法 50 ｜ 近似 22
```

| 字段 | 含义 | 怎么用 |
|---|---|---|
| 综合（等级+加权分） | 108 法按权重与保真度加权平均后的总断 | 先报这个 |
| 一致性 | 1 − 加权标准差/100。越高说明诸法越一致 | <0.25 要直说"分歧大，不宜作决断依据" |
| 置信 | 一致性 × 起卦覆盖率 | 反映这次求占本身可不可靠 |
| 票型 | 吉/平/凶三档法数 | 一眼看倾向 |
| 五行旺缺 | 各法给的五行信号归一化 | 断气机偏向 |
| 共识 | ≥3 法同现的关键词（次数×平均分） | **最可信的部分**，优先讲 |
| 应期 | 多法给出的时间信号 | 有共识的应期才讲，别自己推 |
| 分类 | 每类的加权分 | 看哪类术法偏吉/偏凶 |
| 分歧 | 同类内分差 ≥60 的极端对 | **必须如实转述**，不要抹平 |
| 保真 | 三档法数 | ⚠ 项要说明是近似 |

明细表格式：`编号 名称 符号⚠ 分值 依据`，符号为
`◎大吉 ○吉/小吉 ·平 △小凶 ▲凶 ×大凶`。

## 六、保真度三档（必须如实转述）

| 档 | 含义 | 举例 |
|---|---|---|
| `full` 全算法 | 公开算法完整实现 | 历法、六爻纳甲、梅花、小六壬、称骨、掷筊、二十八宿 |
| `core` 核心算法 | 核心公开算法，部分细节按通例取值 | 奇门局数、六壬课体、紫微安星、玄空飞星 |
| `approx` 近似 ⚠ | 缺秘传表或辞书，按公开可推部分计算 | 铁板类神数、七政四余（无星历表）、签诗辞、面相手相（无图像输入） |

**转述纪律**：`approx` 项在输出里带 ⚠。讲到它们时必须说明"此为近似"。
**本插件不伪造签诗原文、秘传条文、星历表** —— 若用户要签诗全文，告诉他
插件出签号/签级/卦象，原文需另附签谱。

## 七、常见错误（不要犯）

1. ❌ 自己算一卦再和插件对照 —— 白费 token，且你算的不可复核。
2. ❌ 把 108 行明细全复述给用户 —— 挑 3-5 法讲，明细用户自己能看。
3. ❌ 抹平分歧 —— 一致性低时必须直说。
4. ❌ 臆造生日 —— 缺 `birth` 就问，命理类没生日只会记为「未起」。
5. ❌ 用户说"再算一次"时传上次的 `seed` —— 那会得到完全一样的结果。
6. ❌ 把 ⚠ 近似项当实测结论。
7. ❌ 对医疗/法律/重大投资给出决断性建议 —— 必须提示咨询专业人士。
8. ❌ 因为合盘说"凶"就吓唬用户 —— 术数供参考，把决定权交回用户。
