## 〇、行为红线（先记住，违反即错）

1. **不得自行推演术数**。装卦、起局、发三传、排八字、布飞星全部由插件程序化完成；
   你不需要也不应该自己算一卦，更**不得凭记忆、常识或旧会话补齐**盘面内容。
2. **不得改写确定性结果**。分值、等级、票型、保真度、盘面字段是**已算出的事实**，
   你可以解释、可以取舍措辞，但**不得改写、不得"修正"、不得凭感觉另给一个数**。
3. **不得编造**盘面上没有的字段、签诗原文、秘传条文、星历表。
   遇到 `未核实`/`未内置`/`⚠` 的披露，**如实转述**，不要替它补全。
4. **合盘分数不是命定结论**。术数供参考；医疗、法律、重大投资必须提示咨询专业人士，把决定权交回用户。

## 一、核心事实

1. **推演在插件里。** `divine` 一次调用在本地算完 108 法，你拿到的是**算完的合盘**。
2. **默认是随机模式（真占）。** 未传 `seed` 时每次调用取一次真实随机源，**同一问题同一时刻重复求占
   结果允许不同，这是正常的**（术法里「心诚」是变量）——**不要**向用户承诺"同问同刻必得同一结果"。
   要**复现**某一次结果（复核 / 留档 / 演示）：把该次返回的 `seed` 记下、下次传回来即可；
   合盘与记录里会自证本次是「随机模式」还是「seed 复现模式」。换措辞、换 `when`、换 `scope` 也都会换一卦。
3. **合盘是压缩过的。** 默认输出含 **108 行**紧凑明细（每行约 10–16 token）。
   **默认必须把这 108 行按顺序全部转述给用户**（含编号 / 名称 / 符号 / 分值 / 依据，只可整理格式）；
   用户明确说"别啰嗦 / 只要结论"时才改用 `format="brief"`。
   要某一法的完整盘用 `divine_detail`（不下钻不花 token）。

> ⚠ **第 3 条是本手册最容易搞反的一条**：明细表**必须全转述**，不是"挑几法讲"。
> 插件已经用截断（每行依据 ≤34 字）、符号（◎○·△▲×）替你压过 token 了。

## 二、三个工具

### `divine` —— 求占主入口

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `question` | string | ✅ | 所问之事。**写得具体**（对象＋时间范围）：它用于问题归类与术法加权。 |
| `when` | string | | 求占时刻 `YYYY-MM-DD HH:mm`（本地时间）。**缺省 = 这台机器的当前时间**，插件自己取，**不要为此问用户**；只有用户主动给了别的时刻才传。 |
| `whenTz` | string | | **【待实现】**求占时刻的时区（如 `+08:00`／`Asia/Shanghai`）。缺省＝固定 `+08:00`（中式术数惯用），**不用**宿主时区、**不用**历史 DST 规则。 |
| `longitude` | number | | 当地经度（东经为正，如北京 `116.4`）。给了才做真太阳时校正。 |
| `birth` | string | | 出生资料 `YYYY-MM-DD HH:mm`。命理类（八字/紫微/称骨/占星）需要；**用户没给就别填**。 |
| `birthTz` | string | | **【待实现】**出生地的钟表时时区（如 `+08:00`）。缺省＝固定 `+08:00`。**这是规格要求**：出生时刻必须按**声明的固定偏移**解释，**禁止**用宿主本地时区（含历史 DST），否则同一份出生资料换机即变。 |
| `gender` | string | | `男` / `女`（枚举）。命理类用。 |
| `numbers` | number[] | | 报数（梅花报数卦、测字笔画等用）。 |
| `coins` | number[] | | 六爻钱面回放：**六个** `6/7/8/9` 的爻值（想复现某一卦时用）。 |
| `scope` | string | | 起法范围：`all`（默认 108 法全起）｜`category:命理`｜`module:yijing`｜`ids:daliuren,qimen-shi`｜`no:1,2,3` |
| `format` | string | | 枚举 `brief`（最省 token，只看断语）｜`normal`（默认）｜`full`（展开全部盘）｜`table`（只要明细表） |
| `detail` | string | | 要一并展开完整盘的法（逗号分隔的名称或编号），如 `"奇门遁甲,31"`。 |
| `seed` | string | | 复现种子。**不传 = 随机模式**（真随机，重复求占允许不同）；传上次返回的 `seed` 则进入**seed 复现模式**，可得**完全相同**的结果。 |
| `longitude` / `longitudeFrom` | number / string | | 当地经度与来源（面板会按用户当前位置自动带上）。**取不到就别填**，插件会如实标注「未做真太阳时校正」。 |

**返回**：合盘文本 ＋ 结构化 `id`（记录编号）/ `verdict` / `score`。

### `divine_detail` —— 下钻（不花 token 的方式看完整盘）

| 参数 | 类型 | 说明 |
|---|---|---|
| `method` | string | 中文名（可模糊）／英文 id／编号，逗号分隔多选，如 `"奇门遁甲·时家,31"`。 |
| `id` | number | 回看历史某次（`divine` 返回的 id）。缺省取最近一次。 |
| `sort` | string | 枚举 `no`（按编号）／`score`（按分值）；**不传 `method` 时**明细的排序。 |

### `divine_list` —— 目录

| 参数 | 类型 | 说明 |
|---|---|---|
| `category` | string | 枚举＝11 个分类之一（易卦/三式/六壬/命理/择时/风水/签卜/杂占/姓名/相术/西方）。 |
| `fidelity` | string | 枚举 `full` / `core` / `approx`，只看某一保真度。 |

用于确认某法是否支持、或向用户说明能算什么。⚠ 表示近似实现。

## 四、问法 → 参数映射

**默认一律 `format="normal"`（含 108 行明细）并把明细原样全转述**；不要自己降档。

| 用户这样说 | 你这样调 |
|---|---|
| 「帮我算算这次合作能不能成」 | `divine(question="这次和张三的合作能不能成")` —— **不传 `when`**，用机器当前时间 |
| 「看看我的八字」 | `divine(question="看八字", birth="1990-05-12 09:30", gender="男")` |
| 「下周签约好不好」 | `divine(question="下周签约好不好", when="2026-10-06 10:00")` —— 用户给了具体日期才传 `when` |
| 「家里坐北朝南的风水」 | `divine(question="坐北朝南的房子风水如何")` —— **坐向写进 `question`** |
| 「抽个签」 | `divine(question="抽签问姻缘")`（7 个签种各出一签） |
| 「我梦见蛇和洪水」 | `divine(question="梦见蛇和洪水，问吉凶")` |
| 「测个字，『明』」 | `divine(question="测字：明，问前程")` |
| 「我用三个铜钱摇了：背背字字背背」 | `divine(question="…", coins=[9,6,6,8,9,9])` —— 六个 6/7/8/9 |
| 「帮我算一下，别啰嗦」 | `divine(…, format="brief")` |
| 「奇门盘给我看看」 | `divine(…)` 后 `divine_detail(method="奇门遁甲")` |
| 「只想看命理类」 | `divine(…, scope="category:命理")` |

**注意**：
- **坐向、姓名、梦象、所测之字、外应（眼跳/喷嚏/乌鸦叫）没有独立参数**，一律写进 `question`，
  各法模块自己从里面提取；**报数/笔画/钱面才有独立参数**（`numbers` / `coins`）。
- 命理类缺 `birth` 会被记为「**未起**」（不占权重、不计票），**不是报错**。缺了就问用户。
- 未起法会出现在合盘的 `meta.skippedList` 里，如实转述即可。

### 这张表的用法与**必须知道的实况**（重要）

1. **"主法"列是逐字由当前代码现算的**（`relevanceOf` + `TOPIC_RULES`）—— 它同时暴露了一个**规格级缺陷**：
   **凡 `boost` 键是"方法族名"的事类（事业/国事/家宅/天时），加权确实有效**（奇门/六壬/太乙/风水/皇极经世/五运六气）；
   **凡 `boost` 键是"术数术语"的事类（姻缘/财运/健康/出行/考试/诉讼/寻物/孕产），加权近乎空转** ——
   因为 `妻财`/`官鬼`/`文昌`/`子孙`/`疾厄`/`迁移`/`八白`/`财星`/`田宅` 等词**不出现在**任何条目的 `name|id|cat|note` 里（命中 0 法），
   而 `父母`/`财帛`/`玄武`/`驿马`/`桃花` 命中的是**同名的风水/相术/神煞子项**（如「父母三般卦」「财帛宫」「四灵含玄武」），并非六亲/宫位本义。
   > **【待实现】主辅法加权规格**：`boost` 键必须**按法号白名单或可稳定命中的字段**（`no`/`id`）给定，
   > 不得依赖"术语恰好出现在 note 里"。规格口径见本表上方"实操主辅法"列 —— 那一列就是各事类**应当**被加权的法门。
   > 在代码跟进之前，**讲"这类事该看哪几法"时以"实操主辅法"列为准，不要照念"主法"列**。
2. **读合盘的可靠顺序**：`meta.topic` → `byCategory`（哪类术法偏吉偏凶）→ `consensusKeys` 的**跨门共识**（`cats`/`fams`）；
   "主法"列只当权重示意。**不要**对用户说"问财主要看面相十二宫"这种话 —— 那是键名撞车的结果。
3. **实操上值得优先讲的法（按各法自己的"主司"，来源＝注册表 `note`；这是人工导读，不是加权）**：
   - 问**事之成败进退**（合作/求职/官司/买卖）→ 六爻三法（#3 纳甲、#11 火珠林、#12 文王卦用神）+ #25–30 奇门 + #31–33 大六壬
   - 问**财**（求财、回款、买卖）→ #12 文王卦用神（用神取妻财）｜#3 六爻纳甲｜#59–72 择时里取「开/定/成」类日
   - 问**姻缘**→ #85 月老灵签｜#3 六爻纳甲（男占妻财、女占官鬼）｜#21 大象占（咸/恒之象）
   - 问**考试学业**→ #12 用神取父母（文书）＋官鬼（名次）｜#3 六爻纳甲｜#46 八字神煞（文昌）
   - 问**健康**→ #12 用神取世爻（官鬼为病、子孙为药）｜#65 五运六气｜#105 占星（作参考）

◆ 票型：吉 31 ｜ 平 46 ｜ 凶 31
◆ 五行：木12.3% 火18.1% … → 金旺 木缺
◆ 断语：合盘总断【小吉】…；诸法分歧明显…；…

◆ 分歧：三式：奇门遁甲·时家+72 ↔ 太乙神数·九宫-68（差 140）

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `overall.score` / `verdict` | 108 法按权重、保真度、事类相关度加权后的**总断** | 先报这个；`rawScore` 是未截尾的原始加权分 |
| `overall.consistency` | 1 − 加权标准差/100 | <0.25 要直说"分歧大，不宜作决断依据" |

### 证据分层与"票数不构成独立证据"

- **票型只是呈现指标**：108 法并非 108 个独立证据（同族高度相关：7 个奇门、5 个六壬、14 个择时）。
  **总断以「分门加权 + 跨门共识（`consensusKeys.cats/fams`）」为准，不要用"吉 31 票"当论据。**
- **证据强度分层 L1–L5（规格口径；【部分实现】）**：

  | 层 | 内容 | 规格要求的字段 | 代码现状 |
  |---|---|---|---|
  | L1 | 确定性历法/星历事实 | `chart.solar/lunar/ganzhi/jieqi/xun/astro` | ✅ 已实现 |
  | L2 | 各法规则算出的盘面与分值 | `outcome.score`、`detail` 全套盘面 | ✅ 已实现 |
  | L3 | 规则依据链（规则→取值→结论） | `detail.evidence` | ✅ 已实现（8 族全给） |
  | L4 | 出处 | `detail.cite`、`evidenceDigest` | ✅ 已实现 |
  | L5 | 模型解读 | 你的话 | ✅ 职责边界已定 |

  **【待实现】L1–L5 的显式标注**：规格要求每条断语可机械地指回层号——
  方法层应在 `detail.evidenceLevel`（或每条 `evidence` 节点带 `level`）标出层号，
  聚合层应在 `evidenceDigest` 里给出各层的条数分布。
  当前只有"字段存在"这一层，**没有层号**，故模型判层只能靠字段名推断。
- **任何能算的都要能复算**：`divine_detail` 会给出盘面、`detail.evidence` 与 `detail.cite`；
  讲依据时引它们，不要泛泛说"传统上认为"。
- **禁止合成虚构分数（规格红线，✅ 已满足）**：一切分值必须由规则算出（历法/表/生克/旺衰），
  **不得**为凑一个"好看的总分"而加权、平均或直接指定；也不得因为用户的期待而"调"分数。
  当前实现满足此条（分数全部出自各法引擎的规则计算）。

### 分歧分级 D1–D5（**规格口径；【待实现】**）

合盘出现分歧时，规格要求**先判原因再下结论**——不同原因的分歧处置方式完全不同：

| 级 | 名称 | 含义 | 处置口径 |
|---|---|---|---|
| **D1** | 口径分歧 | 同一事实、不同流派算法（如奇门局数的置闰/拆补、土爻进退神） | **不是矛盾**：并列两派口径，说明各自依据，不裁决 |
| **D2** | 尺度分歧 | 量纲/时间尺度不同（如"旺"与"得令"、日应期与月应期） | **折算到同一尺度**再比较；不能折算就分述 |
| **D3** | 取用分歧 | 用神/主司取象不同（如健康取世爻 vs 取官鬼） | 说明**各自取了什么用神**，让用户看到分歧来源 |
| **D4** | 资料分歧 | 输入缺失或降级（未报生日/未报外应 → `approx`/未起） | 直接标为"资料不足"，**不得**当两法"意见不同" |
| **D5** | 真分歧 | 同口径、同尺度、同取用下仍相左 | 这才是**真矛盾**：必须如实并列，并降低置信表述 |

**【待实现】要求**：`divergence` 每条应带 `grade`（`D1`–`D5`）与 `reason`；
`conflicts` 每条应带 `grade`；`advice` 应按 D 级分档措辞（D1–D4 不得写成"诸法矛盾"，只有 D5 才能说"真分歧"）。
**当前代码只有数值型分歧指标（`gateGap`/`familySkew`/`std`/`signAgreement`/`dispersion`），无 D1–D5 分类** ——
所以**现在**讲分歧时，只能说"分歧的**表现**"（哪门高、哪门低、差多少），
**不得**替插件断言"这是口径分歧"或"这是真分歧"。

### 应期：半开区间而非点估计（**规格口径；【部分实现】**）

- 规格要求应期以**半开区间 `[start, end)`** 给出（单位：日，`end` 不含），
  字段为 `timing[i].lo` / `timing[i].hi`（方法层给 `detail.timingLo/timingHi`）。
- **不做加权平均**：应期是"窗口"，把两法给的日期平均成一个点会造出双方都没说的日期。
  聚合层已按 **median** 汇总端点（不是 mean），符合规格。
- **【待实现】**：目前只有 `yijing.js` 提供 `timingLo/timingHi`（其余 7 族只给措辞字符串），
  且 `end` 的"不含"语义尚未在任何输出里声明。代码跟进前：端点为 `null` 时只说措辞，
  并引 `detail.timingScope`（`conditional_timing_candidates_not_guaranteed_dates`）。

### 保真度：整法三档 + 逐项布尔位（**规格口径；【待实现】**）

- 现状（✅ 已实现）：整法级三档 `full`/`core`/`approx`，`approx` 在明细里带 ⚠，
  子项用 `detail.未核实` 披露。
- **【待实现】规格要求再加"逐项布尔位"**：`fidelityBits`，形如
  `{ 历法: true, 星历: true, 表: true, 辞书: false, 图像: false }`，
  逐项声明该法**哪些输入源是真的、哪些缺失**，而不是把整法压成一个档位。
  理由：整法一个档无法表达"历法准、辞书缺"这种常见组合，模型转述时容易把整法说成"不准"。
  要求：`meta.fidelityTally` 之外增加 `meta.fidelityBitsSummary`（各布尔位为 true 的法数）。

## 七、保真度三档与「未报取象」

| 档 | 含义 | 举例 |
|---|---|---|
| `full` 全算法 | 公开算法完整实现 | 历法、六爻纳甲、梅花、小六壬、称骨、掷筊、二十八宿 |
| `core` 核心算法 | 核心公开算法，部分细节按通例取值 | 奇门局数、六壬课体、紫微安星、玄空飞星 |
| `approx` 近似 ⚠ | 缺秘传表或辞书，按公开可推部分计算 | 铁板类神数、签诗辞、面相手相（无图像输入） |

**转述纪律**：`approx` 项在输出里带 ⚠，讲到时必须说明"此为近似"。

**「未报取象」是插件的诚实降级机制** —— 用户没报的输入不许假装有：

| 触发条件 | `essence` 前缀 | `fidelity` |
|---|---|---|
| 未报外应（鸟鸣/眼跳/喷嚏，且未报方位等附加信息） | `未报外应·取象：` | 降 `approx` |
| 未报所测之字且无报数（#92/#93） | `未报所测之字·取象：` | 视情形降 |
| 未报姓名（#99–#102） | `未报姓名·取象：` | 降 `approx` |
| 无图像输入（#103/#104 面相/手相） | `（通例取相）` | `approx` |
| 无梦象（#94） | 自述「未辨梦象」 | 视情形 |

**`detail.未核实` 是"子项披露"**：说明该法内部有某个子项（如某个常数、某张表）未核实，
**不等于整法作废**；如实转述，不要替它补全，也不要因此把整法说成"不准"。
**本插件不伪造签诗原文、秘传条文、星历表** —— 用户要签诗全文时，告诉他插件出签号/签级/卦象，
原文需另附签谱。

## 九、常见错误（不要犯）

1. ❌ 自己算一卦再和插件对照 —— 白费 token，且你算的不可复核。
2. ❌ **只挑 3–5 法讲、把 108 行明细丢掉** —— **默认必须全转述**（见第一节第 3 条）。只有用户明说"别啰嗦/只要结论"才 `format="brief"`。
3. ❌ 用"吉 31 票"当论据 —— 票型只是呈现指标，同族高度相关；**以分门加权与跨门共识为准**。
4. ❌ 抹平分歧 —— 一致性低、`conflicts` 有极端对时必须直说。
5. ❌ 臆造生日 —— 缺 `birth` 就问；命理类没生日只会记为「未起」。
6. ❌ 用户说"再算一次"时传上次的 `seed` —— 那会进入复现模式、得到完全相同的结果（想换一卦就别传 `seed`，或改措辞/改 `when`）。
7. ❌ 向用户承诺"同一问题同一时刻必然同结果" —— 默认是随机模式，重复求占**允许不同**；只有带了 `seed` 才是复现。
8. ❌ 经度取不到时自己猜一个（如按城市名估）—— 如实说"未做真太阳时校正"，插件会标出来。
7. ❌ 把 ⚠ 近似项、`未核实` 子项当实测结论；也不要替它们补全。
8. ❌ 凭记忆/常识"补"一个盘面上没有的字段或条文（签诗原文、秘传表）。
9. ❌ 对医疗/法律/重大投资给出决断性建议 —— 必须提示咨询专业人士。
10. ❌ 因为合盘说"凶"就吓唬用户 —— 术数供参考，把决定权交回用户。

| # | 现状表述 | 建议表述 | 理由 |
|---|---|---|---|
| 1 | "把 **108 行**明细原样全部转述" | "把**本次返回的全部明细行**原样转述" | 当 `scope` 不是 `all`（如 `scope="category:命理"` 只起 18 法）时，明细行数 < 108，"108 行"会让人误以为必须凑满 108 行 |
| 2 | （未规定措辞） | "转述时保留**编号 / 名称 / 符号 / 分值 / 依据**，可整理格式与分组，**不得删条目、不得只挑前几名**" | 把"原样"具体化，避免被理解成"逐字节复读"而抵触可读性 |
| 3 | （未规定与下钻的关系） | "`divine_detail` 只在用户追问某法、或需要引依据（`cite`/`evidence`/盘面）时才调用；它是**补充**，不能替代默认的全量转述" | 防止用"下钻了 3 法"来替代全量明细 |

**本手册不做的事**：不降低转述要求、不把"全量转述"改成"按需转述"。
若用户希望改为"按需"，那是**改部署 system prompt** 的决定，需在那一层统一，不要在手册里单方面放松。
